# calendar-emoji-time-lock-gas

Googleカレンダーの予定名に特定の絵文字が含まれ、指定時刻以降に予定が開始または重なる日に、自動で時間をブロックするスプレッドシート紐づけ型Google Apps Scriptです。

デフォルトでは、タイトルに `🍺` がある予定が18:00以降にかかる日に、`🔒 自動ロック｜夜間予定あり` を18:00〜24:00で作成します。

## 主な機能

- 今日から31日後まで（今日を含め32暦日）の予定を判定
- 17:00〜20:00のように判定開始時刻をまたぐ予定にも対応
- 自動ロックを毎回安全に削除・再生成し、予定変更や削除を反映
- カレンダーID、絵文字、判定時刻、ロック時間、期間などをサイドバーで設定
- 毎日午前3時〜4時に再判定する時間主導型トリガーを重複なく作成
- 20〜30件のランダムなデモ予定を作成・安全に削除
- `UserProperties` による実行ユーザー単位の設定保存

## 利用イメージ

1. `取引先との会食 🍺` が17:00〜20:00に登録されます。
2. 再判定を実行すると、その日の18:00〜翌日0:00に自動ロック予定が作成されます。
3. 元の会食予定を削除して再判定すると、自動ロックも削除されます。

12:00〜13:00の `ランチ 🍺` は18:00以降に重ならないため対象外です。終日予定は初期設定では対象外です。

## 導入方法（GASエディタ）

1. Googleスプレッドシートを新規作成します。
2. スプレッドシートで「拡張機能」→「Apps Script」を開きます。
3. このリポジトリの各ファイルを同名で作成し、内容を貼り付けます。
4. プロジェクト設定でマニフェストファイルを表示し、`appsscript.json` の内容を反映します。
5. スプレッドシートを再読み込みします。
6. メニュー「カレンダーロック」→「設定を開く」を選びます。
7. 初回実行時に表示されるGoogleの権限承認を完了します。

このツールはスプレッドシートに紐づくスクリプトとして利用してください。スタンドアロンスクリプトでは `onOpen` のメニュー表示先がありません。

## GASプロジェクトへの配置方法

`.gs` はスクリプトファイル、`.html` はHTMLファイルとして作成します。HTMLを分割しているため、`Sidebar.html` は `include('Styles')` と `include('JavaScript')` を通じて読み込みます。ファイル名の拡張子を二重にしないでください。

## 必要な権限

- 対象Googleカレンダーの予定の閲覧・作成・削除
- スプレッドシートのUI表示
- ユーザープロパティへの設定保存
- 時間主導型トリガーの作成・管理

共有カレンダーを指定する場合は「予定の変更」以上の権限が必要です。閲覧権限だけでは処理を停止します。

## サイドバーの使い方

「カレンダーロック」→「設定を開く」から設定画面を開きます。設定を変更したら「設定を保存」を押してください。「今すぐ再判定」で即時にロックを更新できます。処理結果には作成件数、削除件数、対象日数が表示されます。

削除操作では確認ダイアログが表示されます。処理中は全ボタンが無効になり、実行ボタンは「処理中…」へ変わります。

## 設定項目一覧

| 項目 | デフォルト | 説明 |
| --- | --- | --- |
| カレンダーID | `primary` | メインカレンダー。共有カレンダーはIDを入力 |
| 判定絵文字 | `🍺` | 予定名に含まれる文字列 |
| 自動生成予定名 | `🔒 自動ロック｜夜間予定あり` | ロック予定のタイトル |
| 判定開始時刻 | `18:00` | この時刻以降に重なる予定を対象化 |
| ロック開始時刻 | `18:00` | 自動ロックの開始 |
| ロック終了時刻 | `24:00` | 自動ロックの終了。24:00は翌日0:00 |
| 判定期間の日数 | `31` | 今日からN日後まで。0〜365 |
| 終日予定を対象にする | オフ | オンの場合、絵文字付き終日予定も対象 |
| 既存ロックを削除して再生成 | オン | 元予定の変更をロックへ反映 |

設定は `PropertiesService.getUserProperties()` に保存されるため、同じスプレッドシートでもユーザーごとに設定が分かれます。

## トリガー設定方法

サイドバーまたはメニューから「毎日実行トリガーを設定」を実行します。既存の `dailyRefreshCalendarLocks` 用トリガーを削除してから、Asia/Tokyoの毎日午前3時台に新しいトリガーを1件作成します。Apps Scriptの仕様により、3:00ちょうどではなく3:00〜4:00の間に実行されます。

## ダミーデータの作成方法

「ダミーデータを作成」を実行すると、今日から60日後までに20〜30件を作成します。時刻は09:00〜10:00、13:00〜14:00、17:00〜19:00、18:00〜20:00、19:00〜21:00、20:00〜22:00からランダムに選ばれます。

すべてのダミー予定の説明欄には次の識別子が入ります。

```text
DUMMY_EVENT_ID: CALENDAR_EMOJI_TIME_LOCK_DEMO
```

## ダミーデータの削除方法

「ダミーデータを削除」は、説明欄に上記識別子がある予定だけを削除します。通常予定と自動ロック予定は削除しません。

## 自動生成予定の安全な削除方法

自動ロックの説明欄には次の識別子が入ります。

```text
SYSTEM_EVENT_ID: CALENDAR_EMOJI_TIME_LOCK
```

削除処理は、現在設定中の自動生成予定名との完全一致と、説明欄の識別子一致を両方満たす予定だけを削除します。同名の手動予定や、似た名前の予定は削除しません。自動生成予定名を変更する場合は、変更前に古い自動ロックを削除してから新しい名前を保存してください。

## トラブルシューティング

### メニューが表示されない

スプレッドシートを再読み込みしてください。スクリプトがスプレッドシートに紐づいていることも確認します。

### カレンダーを取得できない

`primary` またはGoogleカレンダーの設定画面に表示される正確なカレンダーIDを入力してください。共有カレンダーでは編集権限も必要です。

### 権限エラーになる

Apps Scriptエディタから `showSidebar` または `refreshCalendarLocks` を一度実行し、必要な権限を承認してください。組織のGoogle Workspaceポリシーで制限されている場合は管理者へ確認してください。

### 24:00を入力できない

ロック終了時刻欄は文字入力です。半角で `24:00` と入力してください。判定開始・ロック開始に24:00は指定できません。

### 古い名前の自動ロックが残る

安全性のため、削除は現在設定中の予定名にも一致する必要があります。いったん設定を以前の予定名へ戻して自動生成予定を削除し、その後に新しい名前を保存してください。

## claspを使う場合の初期設定

Node.jsとnpmを用意し、claspへログインします。

```bash
npm install -g @google/clasp
clasp login
```

このプロジェクトで使うGoogleアカウントは `nakashima.keitarou@gmail.com` です。複数アカウントを使う場合は、claspの認証先をよく確認してください。

既存のスプレッドシート紐づけGASプロジェクトを使う場合、Apps Scriptの「プロジェクトの設定」にあるスクリプトIDを確認し、リポジトリ直下に次の `.clasp.json` を作成します（このファイルはGit管理対象外です）。

```json
{
  "scriptId": "1vTOQseBHEGan7OvfilZC_-okAhdiKaHFJLjw009lONSP8PwTKthV9gxO",
  "rootDir": "."
}
```

その後、ファイルをGASへ反映します。

```bash
clasp push
clasp open
```

スクリプトIDはメールアドレスではありません。このプロジェクトでは上記IDへの接続を確認済みです。`.clasp.json` は環境固有の接続設定なので、リポジトリには含めません。

新しい紐づけ型プロジェクトを作る場合は、先に対象スプレッドシートのIDを確認して次を実行できます。

```bash
clasp create --type sheets --title "Calendar Emoji Time Lock" --parentId "スプレッドシートID"
```

## GitHubへのpush方法

リポジトリは [groundcobra009/calendar-emoji-time-lock-gas](https://github.com/groundcobra009/calendar-emoji-time-lock-gas) です。本プロジェクトでは、実装前にGitHub Issueを作り、Issue番号付きブランチとPull Requestを使います。

```bash
# Issue #Nを作成した後
git switch -c issue-N-short-english-name

# 対象ファイルだけを追加し、Issue番号をコミットに残す
git add path/to/changed-file
git commit -m "feat: 変更内容 Refs #N"
git push -u origin issue-N-short-english-name

# PR本文にはIssueを自動クローズする記述を入れる
gh pr create --title "【calendar-emoji-time-lock-gas】日本語タイトル" \
  --body "Closes #N"
```

Issue本文には目的・スコープ・受け入れ基準・テスト計画・知見ログを記載します。実装中の判断、ハマりどころ、検証結果はIssueコメントへ追記し、PRのマージ前に品質ゲートを通します。

`.clasp.json` には環境固有のスクリプトIDが含まれるため、このリポジトリでは `.gitignore` に追加しています。
